CONSOLE STEPS (open screen, then click its button)

01 Check runtime | http://127.0.0.1:8788/#prepare
Click Check runtime (or Check runtime again). This verifies Node and recipe files; installation comes at step 03.

02 Wallet + configure | http://127.0.0.1:8788/#configure
Select Wallet and follow the setup command. Select Strategy, paste the returned Sui address, then click Save and continue to funding. Funding collects the email for that saved wallet.

03 Install agent | http://127.0.0.1:8788/#deploy
Click Install dependencies (or Install dependencies again). Wait for Dependencies: Installed and check the installation output.

04 Start / run | http://127.0.0.1:8788/#run
Click Run once. Wait for a fresh timestamp and output. Read the actual outcome, including any funding block; an unsigned simulation is not a submitted swap.

05 Inspect | http://127.0.0.1:8788/#inspect
Read HOLD, BUY SUI or SELL SUI, its reason and the separate dry-run status. Proposed amounts are quoted, not transferred. Expand Raw execution output for evidence.

06 Modify | http://127.0.0.1:8788/#modify
Change one threshold, click Apply configuration, then return to 04 Start / run and click Run once.

07 Stop | http://127.0.0.1:8788/#stop
If monitoring is running, click Stop agent. Click Save output to retain the result. A single Run once already exits after its cycle.

BASECAMP PRESENTER COMPANION

00–06 MIN | Why personal agents
SCREEN: Slides
DO: Introduce Muse, Instinct, Dots, OpenClaw and Hermes. Ask what work the room would delegate to an agent.
SAY: An agent needs a place to run, a wallet, a budget and a way to prove what happened.
LOOK FOR: The room has one concrete agent job in mind.
IF STUCK: Keep the opening to six minutes; skip extra examples.

06–11 MIN | Why AEX
SCREEN: Slides + architecture drill-downs
DO: Show the market, runtime, inference and security plane. Walk discover → agree → escrow → run → settle.
SAY: AEX brings the agent, its compute and its spending authority together.
LOOK FOR: Keep architecture claims separate from today’s installed standalone recipe.
IF STUCK: Use the architecture diagram; AEX self-deployment is not required for this route.

11–16 MIN | Authority and budget
SCREEN: Slides
DO: Explain ownership, limits and the four budgets: AEX, WaaP, transaction gas and position capital.
SAY: The local build has no AEX deployment fee. A proposal, a simulation and a confirmed transaction are different results.
LOOK FOR: No one interprets a funding registration receipt as a payment or an unsigned simulation as a swap.
IF STUCK: Do not promise an allowance until the complete funded recipe has been measured.

16–20 MIN | Tour one agent
SCREEN: Deck → runtime console
DO: Show the seven controls. Explain where each action runs: local computer for builders; verify the connected host when using a Studio tunnel.
SAY: Check the runtime. Set up a wallet. Save the strategy. Install the agent. Run and inspect it. Change a rule, then stop.
LOOK FOR: The audience understands the sequence before downloading.
IF STUCK: Keep Guardian as a later recipe. Finish one working Rebalancer first.

20–25 MIN | Build QR and wallet setup
SCREEN: Build QR → deployment guide → console
DO: Show Build QR and the full URL. Builders install Node 24, unzip the kit and run PORT=8788 node server.mjs --open (or PORT=8789 for the separate local rehearsal). Step 01 checks Node; step 02 runs node wallet-setup.mjs in a second terminal. They create or sign in, approve email, copy the Sui address into Strategy, and save.
SAY: Use your own email and wallet. Once saved, the Funding panel includes that wallet address automatically.
LOOK FOR: Wallet setup prints an email and full Sui address. Strategy contains that same address. No historical example is used for funding.
IF STUCK: Pair with a laptop that is ready. Choose port 8789 below for a separate local rehearsal, or 8788 to reuse the existing console. Keep the selected port and launch command matched. Node 26 is not the tested runtime.

25–34 MIN | Register, install and run together
SCREEN: Funding QR → operator → runtime console
DO: When wallets are ready, open slide 17 for the Funding QR. Registration accepts submissions without starting a timer. Optionally start a 15-minute reminder on the private operator screen. Builders enter email in Funding; direct QR users enter email and address. After registration, open slide 18. Use the numbered console links below. Open 03 Install agent and click Install dependencies. Wait until Dependencies reads Installed. Open 04 Start / run and click Run once. Read the new output before proceeding.
SAY: The install button runs npm ci. Installation does not start the agent. One run reads actual wallet balances and the live Sui pool.
LOOK FOR: Show installation events, then a fresh checkpoint, price, balances and outcome from the funded presenter wallet.
IF STUCK: If funding is not ready, explain the actual balance block. Continue installation while funding is processed; do not present historical results as a new run.

34–40 MIN | Change one strategy rule
SCREEN: Runtime Modify → Run → Inspect
DO: With a rehearsed funded configuration, change one threshold and run again. Compare HOLD against a proposed action. Inspect quote, unsigned build and Sui simulation separately.
SAY: The rule changed. Now compare the inputs and explain why the result changed.
LOOK FOR: Each output is timestamped and has the current configured wallet. A simulation is explicitly labelled.
IF STUCK: If price or holdings do not meet the rule, explain HOLD. Do not invent a trade. A signed swap is only shown after its separate funded rehearsal passes.

40–57 MIN | Independent build + funding handoff
SCREEN: Participant consoles + private funding operator
DO: When ready to fund, refresh operator controls and export campaign.json and responses.csv. The first 30 unique registrations are selected in server order; the rest join the waitlist. Pass both to the payout agent with the approved allowance, total, source account and reserve. Review the exact plan before sending. Builders check receipts, run, modify and stop their own agent.
SAY: Keep one result you can explain: the rule, the live inputs and the output.
LOOK FOR: At most 30 selected recipients; waitlisted builders can continue setup. Every sent payment has its own checked receipt.
IF STUCK: An unresolved payment stops payout processing. Never create a second ledger to retry. Allowance and source authentication must be ready before live sending.

57–60 MIN | Close
SCREEN: Closing slide
DO: Ask what they will build next. Link the deployment guide and canonical recipe. Confirm the presenter’s monitoring is stopped.
SAY: Keep the recipe, your configuration and your evidence.
LOOK FOR: Builders know the next step and the session ends on time.
IF STUCK: No operator checklist or setup appendix in the audience deck.
