Deploy the Sui Rebalancer.

A standalone process that reads a real Sui wallet and market, evaluates price limits, and prepares a swap for simulation. No AEX account is required.

1. Prepare Node 24

Install Node.js 24 if it is not already available. The console checks the version before deployment.

Get Node 24 ↗

2. Download and open the kit

Download Rebalancer kit

Unzip the download first. The extracted folder is named sui-rebalancer.

Mac

  1. Open Terminal.
  2. If you extracted the kit in Downloads, copy and paste the command below, then press Return. Otherwise type cd , drag the extracted folder into Terminal, press Return, then run node server.mjs --open.
  3. The console opens in your browser. Keep Terminal open while building.
cd ~/Downloads/sui-rebalancer && node server.mjs --open

Start.command is an optional double-click launcher. If macOS says it cannot verify the file, dismiss the dialog and use the Terminal command above to run the kit’s source directly. Typing start.command alone does not launch a file from the current folder.

Windows

Open Start.cmd from the extracted folder, or open a terminal in that folder and run:

node server.mjs --open
Node version or console already running?

Run node --version. This kit requires v24.x; v26 is not the tested runtime. After installing Node 24, open a new Terminal and check again.

If a Rebalancer console already uses port 8788, the updated launcher opens that console without starting another. It may be running locally or connected to Studio. With an older kit, EADDRINUSE means that port is occupied: open the local console link below. If it is a different application, ask for help before stopping it.

Open local console ↗

3. Deploy, run and inspect

  1. Prepare: verify Node and the recipe files.
  2. Wallet + configure: create or sign in to your wallet and complete its email approval. Copy its Sui mainnet receive address into the console, set the strategy and save.
  3. Fund the wallet: match the saved address to your wallet before receiving the agreed allocation. Verify the transfer receipt and balance before the first funded run.
  4. Deploy: install the exact dependency lockfile.
  5. Run once: read actual balances and the live market. Inspect the strategy outcome.
  6. Inspect: distinguish an observation, quote, unsigned build and transaction simulation.
  7. Modify: stop scheduled runs, change one rule, then run again.
  8. Stop: stop the process and schedule, then save the output.

The wallet field starts empty. Enter a verified wallet you control. Older installations may show a historical example address; do not fund that address. An empty wallet returns a funding error; it never becomes sample holdings.

Current execution mode

Live mainnet reads and unsigned transaction simulation. The kit contains no signer and cannot submit a swap. A successful simulation is separate from a confirmed transaction. No AEX, WaaP or transaction fee is charged by this unsigned path; normal internet and local compute costs apply.
